The booking's status along the way

Rules the flow keeps

  • Picking a flight reserves nothing. Only a successful seat hold does, and it lasts 20 minutes. The payment deadline is 5 minutes earlier.

  • Prices come from the server. The browser only shows them. The payment order takes its amount from the booking service, never from the page.

  • Paid is not booked. The booking is confirmed only when the airline returns a PNR and the tickets. No ticket is shown before that.

  • Nothing happens twice. A double click returns the same booking. The airline order uses the booking id as its key, so after a timeout the order is looked up, never placed again.

  • Payments are checked twice. The signature from the checkout is verified and the payment is fetched from Razorpay; the webhook confirms it again, and a job every 5 minutes catches closed tabs.

  • Money always comes back. If the airline rejects the order, or a payment arrives after the booking expired, the full amount is refunded.

Behind the dashed arrows

The services talk through Kafka events. Each service skips an event it has already handled, so a repeated or late message changes nothing.
